## 相对原安装版本的行为变化

| 场景 | 原安装版本 | 本机优化版本 |
| --- | --- | --- |
| 正在运行 | 红色，已收录任务持续保留 | 红色；仅可确认运行的任务显示 |
| 正常结束 | 已收录任务一直保留绿色 | 一般仅保留 Codex 标记未读的任务 |
| 启动前已经结束且未读 | 历史完成任务通常不收录 | 收录本机未读的正常完成任务 |
| 完成时仍停留在会话 | 不区分是否阅读 | 已观察到的完成单独保留绿色，不接受自动清除未读作为阅读证据 |
| 特殊完成项的后续变化 | 无独立阅读状态 | 新一轮转红；其他非显示状态移出；明确切到其他会话再回来才按已读移出 |
| 看板刷新/重启 | 刷新保留，重启重新收录 | 特殊待阅读、离开与确认状态按轮次持久化 |
| 等待、中断、失败、未知 | 黄色/灰色色块 | 无色块；全局读取或连接错误清空色块并提示 |
| 未读数据异常 | 没有未读数据依赖 | 一般完成项隐藏；保留运行项及已记住的特殊待阅读项，并提示 |

绿色始终只表示本轮正常结束且待阅读，不表示项目验收完成。

- `SKILL.md`：同步筛选、特殊保留、缓存位置和 Windows 选择识别边界。
- 新增 `tests/test_visibility.py`：16 项场景回归，覆盖未读切换、一直停留、回访、新轮次、延迟标记、错误恢复、标题重复和重启保留。

- 仓库 `tests/test_local_visibility.py`：把 Skill 内回归测试接入现有 `unittest discover -s tests`。原生命周期测试更新为验证隐藏状态仍正确解析，而不再要求灰黄块；快速新任务测试提供明确未读标记；测试隔离真实桌面选择信号。

2. **快照接口冲突**：主线使用 `attention`、`read_state_error`；本机使用 `visibility_warning`，不输出逐项关注列表。合并时同步处理 reader、server、网页、启动器及对应测试。

4. **平台与版本**：原生回访识别仅在 Windows 实现；macOS 需要自己的选择信号或明确的降级方案。服务版本号也需统一。
5. **测试与文档**：两边修改了相同筛选断言及颜色说明；应同时保留生命周期/启停测试和本分支新增的阅读状态覆盖。

## 已知限制，不作为已解决问题

- 特殊保留依赖同一 Monitor 先观察到任务，再观察到新的完成状态。服务未运行期间已完成并自动清除未读的任务，或首次看到便已完成的全新短任务，不能补认；普通明确未读任务仍可显示。
- 回访目前只能通过可识别的会话间切换确认；切到非会话页面未必可识别。最小化、侧栏不可读、重复标题、多窗口歧义、Codex 控件/进程布局变化均可能使选择未知，此时不会推断已读。
- 服务每轮读取后等待 2 秒；原生查询还可能耗时或达到 3 秒超时，因此快速切走又回来可能漏观测，保留绿色。
- 非 Windows 环境返回未知选择。特殊绿色仍可能建立并持久化，但不会因回访自动清除；新轮次、归档等后续变化仍能改变其状态。不能把此分支表述成已完成跨平台回访支持。
- 正在运行但 5 分钟没有日志更新的任务仍会被隐藏；原日志延迟问题没有在本次保存中修复。
- 一般状态依赖 Codex 写盘时机；内部格式兼容性及原生 UIA 选择需要在目标 Codex 版本重新确认。看板并不读取对话正文来推断用户是否阅读。
